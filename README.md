# Dream Player — GTK (Linux)

> **Этот проект создаётся полностью с помощью ИИ** (Claude, Anthropic): код,
> структура, интерфейс, переводы и документация написаны ИИ-инструментами по
> постановке автора.
>
> **This project is created entirely with AI** (Claude by Anthropic).

Десктопный фронтенд для Linux на **GTK 4 / gtkmm (C++20)** поверх ядра
[rs_dream_player](https://github.com/ksimilikon/rs_dream_player) (Rust). Работает с ядром
только через его C ABI (`init`, `idx_*`, `engine_*`, `cdc_*`, `con_*`, `sync_*`, `mods_*`).
Ориентиры по функциям — TUI ядра и [android_front_player](https://github.com/ksimilikon/android_front_player).

## Возможности

- **Вкладки.** Стартовая — список плейлистов (не закрывается). Остальные открываются
  по ходу работы и закрываются: плейлист, редактор / создание плейлиста, обзор песни,
  настройки, синхронизация, импорт, экспорт, логи, моды, вкладки модов, «О программе».
  Повторное открытие той же сущности фокусирует уже открытую вкладку.
- **Панель проигрывания сверху:** обложка, название, исполнители; нижняя граница —
  тонкая зелёная полоса прогресса, которая утолщается при наведении (ползунок можно тянуть).
  На фоне — три полупрозрачные синусоиды в цвете акцента: пока играет музыка, они
  дрейфуют влево / вправо, а их амплитуда, длина, скорость и уровень плавно блуждают
  в небольших диапазонах, выбранных случайно при запуске. На паузе волны замирают и
  не тратят CPU. Клик по панели — обзор текущей песни.
- **Кнопки управления** собраны компактной группой снизу справа: перемешивание,
  предыдущая, играть / пауза, следующая, повтор песни, громкость.
- **Пробел** — играть / пауза, когда окно активно (в текстовых полях пробел печатается).
- **D-Bus / MPRIS** (`org.mpris.MediaPlayer2.dream_player_gtk`): медиаклавиши, виджет
  плеера рабочего стола, `playerctl`; метаданные с обложкой.
- **Редактор плейлистов:** название, обложка, порядок, добавление из библиотеки с поиском,
  предпрослушивание.
- **Обзор песни:** теги с записью в файл, обложка (файл / встроить в теги), цвет, метка,
  громкость песни, «хранить без плейлиста», технические сведения.
- **Импорт / экспорт** пакетов `.dplr` (библиотека, выбранные плейлисты или песни).
- **Синхронизация** с другим устройством (ПК, TUI ядра, Android): ожидание / подключение
  по TCP (порт 47800), USB через `adb forward` / `adb reverse`; сопряжённые устройства
  (переименовать, забыть). Протокол, сопряжение и шифрование — в ядре.
- **Моды ядра** (подсистема в предальфе): вкладка «Моды» в меню — список, включение /
  выключение (запоминается), добавление `.so`, вкладки модов (элементы `Text`, `Image`,
  `Input`, `Button`, `List`, `Box`, `Info`, `Toggle`, `Select`), действия модов в главном
  меню и контекстных меню плейлистов / песен.
- **Логи** приложения и ядра с фильтром по уровню; строка статуса внизу.

## Сборка

Нужно: `meson` ≥ 1.1, `ninja`, компилятор C++20, `gtkmm-4.0` (≥ 4.10), Rust (`cargo`),
исходники ядра рядом: `../rs_dream_player`.

```sh
meson setup build          # -Dcore_dir=/путь/к/rs_dream_player -Dcore_profile=debug
ninja -C build             # ядро собирается cargo (--features modding) автоматически
./build/dream_player_gtk
```

Установка: `meson install -C build` (бинарник, `libdream_player.so`, ресурсы, `.desktop`).

## Где что лежит

| что | путь |
|---|---|
| настройки приложения | `~/.config/dream_player_gtk/settings.conf` |
| библиотека, ключи устройства, моды | `~/.local/share/dream_player_gtk/` (`mods/` — сюда класть `.so`) |
| кэш | `~/.cache/dream_player_gtk/` |
| ресурсы (языки, темы, лицензии) | `data/` в исходниках или `<prefix>/share/dream_player_gtk/` |

`DREAM_PLAYER_GTK_DATA` переопределяет каталог ресурсов.
`DREAM_PLAYER_GTK_OPEN="settings,song:1,playlist:Имя,library,editor:,mod:/путь/мод.so:0"` —
отладочное: открыть вкладки при запуске.

## Локализация

Текстовые файлы `data/lang/<код>.lang`: строки `ключ = текст`, `{0}`, `{1}` — подстановки,
`\n` — перенос, `#` — комментарий, `@name` — название языка. Поиск строки: выбранный язык →
`en.lang` → сам ключ. Язык — «Системный» (из `LANG`) или выбранный в настройках
(применяется после перезапуска). Новый язык = новый файл, код менять не нужно.

## Темы

`data/themes/<id>.theme` — токены цветов (`bg`, `surface`, `surface_alt`, `border`, `text`,
`muted`, `accent`, `accent_text`, `warning`, `error`); `data/themes/style.css` — шаблон
стилей, где `{{токен}}` заменяется значением темы. Сейчас есть тёмная тема: чёрный фон,
зелёный акцент, предупреждения — жёлтые, ошибки — красные. Своя тема = копия `dark.theme`
под другим именем; она появится в настройках и применяется сразу.

## Структура

```
src/
  core/     ffi.h (C ABI ядра), обёртки: Library, Player (очередь), Covers, Mods,
            Exchange (импорт/экспорт), SyncWorker (транспорт синхронизации)
  dbus/     MPRIS
  i18n/     локализация из текстовых файлов
  theme/    темы из текстовых файлов
  ui/       MainWindow, TabHost (механизм вкладок), Menus, widgets/, tabs/
  util/     Log, Settings, Paths, Format, MainThread
data/       lang/, themes/, лицензии, .desktop
```

## Известные ограничения

- C ABI ядра в бете: `src/core/ffi.h` написан вручную по исходникам `api/` и
  `mod_sys/` и должен обновляться вместе с ядром.
- Некоторые вызовы ядра (индексация, упаковка, импорт) держат его блокировку долго —
  на это время опрос позиции плеера приостанавливается.
- `FFIPlaylist` не отдаёт id плейлиста, поэтому действия модов в меню плейлиста
  получают `target = 0`.
- Bluetooth и USB без adb (AOA), которые есть в TUI, пока не перенесены.
