# Dream Player — GTK (Linux)

> **Этот проект создаётся полностью с помощью ИИ** (Claude, Anthropic): код,
> структура, интерфейс, переводы и документация написаны ИИ-инструментами по
> постановке автора.
>
> **This project is created entirely with AI** (Claude by Anthropic).

Десктопный фронтенд для Linux на **GTK 4 / gtkmm (C++20)** поверх ядра
[rs_dream_player](https://github.com/ksimilikon/rs_dream_player) (Rust). Работает с ядром
только через его C ABI (`init`, `idx_*`, `engine_*`, `cdc_*`, `con_*`, `sync_*`, `mods_*`).
Ориентиры по функциям — TUI ядра и [android_front_player](https://github.com/ksimilikon/android_front_player).

## Возможности

- **Вкладки.** Стартовая — список плейлистов (не закрывается). Остальные открываются
  по ходу работы и закрываются: плейлист, редактор / создание плейлиста, обзор песни,
  настройки, синхронизация, импорт, экспорт, логи, моды, вкладки модов, «О программе».
  Повторное открытие той же сущности фокусирует уже открытую вкладку.
- **Панель проигрывания сверху:** обложка, название, исполнители; нижняя граница —
  тонкая зелёная полоса прогресса, которая утолщается при наведении (ползунок можно тянуть).
  На фоне — три полупрозрачные синусоиды в цвете акцента: пока играет музыка, они
  дрейфуют влево / вправо, а их амплитуда, длина, скорость и уровень плавно блуждают
  в небольших диапазонах, выбранных случайно при запуске. На паузе волны замирают и
  не тратят CPU. Клик по панели — обзор текущей песни.
- **Очередь** — отдельная вкладка с `*` в конце названия (например «Вечерний эфир*»). Вкладка
  плейлиста — просто список песен; запуск воспроизведения переключает на вкладку очереди
  (прокрутка сбрасывается). Порядок меняется перетаскиванием, очередь можно сохранить как
  плейлист (если имя занято — плейлист перезапишется, об этом пишется красным под полем).
  Закрытие вкладки `*` останавливает воспроизведение и очищает очередь. Другой плейлист можно
  добавить в очередь после текущей песни или в конец.
- **Кнопки управления** собраны компактной группой снизу справа: перемешивание, предыдущая,
  играть / пауза, следующая, повтор песни, без звука. Вся пустая часть нижней панели —
  регулятор общей громкости (клик / перетаскивание), в ней же пишется последнее сообщение.
- **Горячие клавиши** (настраиваются и отключаются в настройках, не зависят от раскладки):
  пробел — играть / пауза; ↑/↓ — общая громкость; ←/→ — переключение песни; Ctrl+↑/↓ —
  громкость текущей песни; Ctrl+←/→ — перемотка; Ctrl+S — сохранить изменения; Ctrl+W,
  Ctrl+Tab, Ctrl+N, Ctrl+, , Ctrl+Q; Ctrl+R — переиндексация (на вкладке плейлистов). Колёсико мыши ползунки не меняет.
- **D-Bus / MPRIS** (`org.mpris.MediaPlayer2.dream_player_gtk`): медиаклавиши, виджет
  плеера рабочего стола, `playerctl`; метаданные с обложкой.
- **Редактор плейлистов:** экран пополам — плейлист и библиотека; перетаскивание внутри
  плейлиста и из библиотеки в плейлист; сортировка библиотеки (название, имя файла,
  исполнители, добавлена в библиотеку, файл изменён / создан); «скрывать уже добавленные»;
  предпрослушивание песни из контекстного меню. При закрытии с несохранёнными изменениями —
  «сохранить / не сохранять / отмена».
- **Обзор песни:** по умолчанию только просмотр; обложка по центру, вдоль неё — вертикальная
  громкость песни; список плейлистов, где есть песня. Кнопка «Изменить» включает правку: теги
  с записью в файл, цвет, метка, путь к файлу (файл перемещается), обложка; Ctrl+S сохраняет.
- **Обложки:** у каждой песни в списках (загружаются в фоне); у плейлиста без своей обложки —
  обложка первой песни.
- **Импорт / экспорт** пакетов `.dplr` (библиотека, выбранные плейлисты или песни).
- **Синхронизация** с другим устройством (ПК, TUI ядра, Android): ожидание / подключение
  по TCP (порт 47800), USB через `adb forward` / `adb reverse`; сопряжённые устройства
  (переименовать, забыть). Протокол, сопряжение и шифрование — в ядре.
- **Моды ядра** (подсистема в предальфе): вкладка «Моды» в меню — список, включение /
  выключение (запоминается), добавление `.so`, вкладки модов (элементы `Text`, `Image`,
  `Input`, `Button`, `List`, `Box`, `Info`, `Toggle`, `Select`), действия модов в главном
  меню и контекстных меню плейлистов / песен.
- **Логи** приложения и ядра с фильтром по уровню; строка статуса внизу.

## Сборка

Нужно: `meson` ≥ 1.1, `ninja`, компилятор C++20, `gtkmm-4.0` (≥ 4.10), Rust (`cargo`),
исходники ядра рядом: `../rs_dream_player`.

```sh
meson setup build          # -Dcore_dir=/путь/к/rs_dream_player -Dcore_profile=debug
ninja -C build             # ядро собирается cargo (--features modding) автоматически
./build/dream_player_gtk
```

Установка: `meson install -C build` (бинарник, `libdream_player.so`, ресурсы, `.desktop`).

## Пакеты для дистрибутивов

```sh
packaging/build.sh            # всё: arch debian ubuntu fedora
packaging/build.sh arch       # или выборочно
```

| цель | дистрибутив | результат | как собирается |
|---|---|---|---|
| `arch` | Arch / Manjaro / EndeavourOS | `.pkg.tar.zst` | `makepkg` на хосте (Arch), иначе в контейнере |
| `debian` | Debian 13 (trixie) | `.deb` | контейнер `debian:trixie` |
| `ubuntu` | Ubuntu 24.04 LTS | `.deb` | контейнер `ubuntu:24.04` |
| `fedora` | Fedora (последняя) | `.rpm` | контейнер `fedora:latest`, `rpmbuild` по `packaging/rpm/*.spec` |

Каждый пакет собирается внутри своего дистрибутива (Docker или Podman), поэтому он
слинкован с его GTK / glibc и ставится штатным менеджером пакетов (`pacman -U`, `apt install
./file.deb`, `dnf install ./file.rpm`). Исходники берутся из рабочих деревьев (вместе с
незакоммиченными изменениями); ядро — из `CORE_DIR` (по умолчанию `../rs_dream_player`).
Результат — `packaging/out/`. Для `.deb` поле `Maintainer` задаётся переменной `MAINTAINER`.

Пакет ставит: `/usr/bin/dream_player_gtk`, ядро как приватную библиотеку
`/usr/lib*/dream_player_gtk/libdream_player.so`, ресурсы `/usr/share/dream_player_gtk/`,
`.desktop`, иконку и AppStream-метаданные.

## Где что лежит

Папка приложения общая с TUI ядра — обе программы видят одну библиотеку:

| что | путь |
|---|---|
| папка приложения | `~/.config/dream_player/` |
| библиотека, ключи устройства, конфиг ядра | `music_db.sqlite`, `keys`, `config.toml` в папке приложения |
| моды (класть `.so` сюда) | `~/.config/dream_player/mods/` |
| настройки GTK-фронтенда | `~/.config/dream_player/gtk.conf` |
| временные файлы (обложка для MPRIS) | `~/.cache/dream_player/` |
| ресурсы (языки, темы, лицензии) | `data/` в исходниках или `<prefix>/share/dream_player_gtk/` |

`DREAM_PLAYER_GTK_DATA` переопределяет каталог ресурсов.
`DREAM_PLAYER_GTK_OPEN="settings,song:1,playlist:Имя,library,editor:,mod:/путь/мод.so:0"` —
отладочное: открыть вкладки при запуске.

## Локализация

Текстовые файлы `data/lang/<код>.lang`: строки `ключ = текст`, `{0}`, `{1}` — подстановки,
`\n` — перенос, `#` — комментарий, `@name` — название языка. Поиск строки: выбранный язык →
`en.lang` → сам ключ. Язык — «Системный» (из `LANG`) или выбранный в настройках
(применяется после перезапуска — приложение предлагает перезапуститься сразу). Новый язык = новый файл, код менять не нужно.

## Темы и палитра

`data/themes/<id>.theme` — токены цветов (`bg`, `surface`, `surface_alt`, `border`, `text`,
`muted`, `accent`, `accent_text`, `warning`, `error`); `data/themes/style.css` — шаблон
стилей, где `{{токен}}` заменяется значением темы. Сейчас есть тёмная тема: чёрный фон,
зелёный акцент, предупреждения — жёлтые, ошибки — красные. Своя тема = копия `dark.theme`
под другим именем; она появится в настройках и применяется сразу. В «Настройки → Палитра»
любой цвет можно переопределить поверх темы (`color.<токен>` в `gtk.conf`).
Формы интерфейса — ретро-терминал: всё квадратное, тонкие рамки, моноширинные подписи.

**Шрифт** (Настройки → Шрифт, применяется сразу): пиксельный — встроенный
[Terminus (TTF)](https://files.ax86.net/terminus-ttf/) (`data/fonts/`, SIL OFL 1.1, шрифт в духе
tty, с кириллицей), по умолчанию; или системный.

## Структура

```
src/
  core/     ffi.h (C ABI ядра), обёртки: Library, Player (очередь), Covers, Mods,
            Exchange (импорт/экспорт), SyncWorker (транспорт синхронизации)
  dbus/     MPRIS
  i18n/     локализация из текстовых файлов
  theme/    темы из текстовых файлов
  ui/       MainWindow, TabHost (механизм вкладок), Menus, widgets/, tabs/
  util/     Log, Settings, Paths, Format, MainThread
data/       lang/, themes/, лицензии, .desktop
```

## Известные ограничения

- C ABI ядра в бете: `src/core/ffi.h` написан вручную по исходникам `api/` и
  `mod_sys/` и должен обновляться вместе с ядром.
- Некоторые вызовы ядра (индексация, упаковка, импорт) держат его блокировку долго —
  на это время опрос позиции плеера приостанавливается.
- Ядро не отдаёт даты песен из базы (`updated_at`): сортировка «изменена в библиотеке»
  пока упорядочивает по порядку добавления.
- `FFIPlaylist` не отдаёт id плейлиста, поэтому действия модов в меню плейлиста
  получают `target = 0`.
- Bluetooth и USB без adb (AOA), которые есть в TUI, пока не перенесены.
